# Перенос лендинга в WordPress

Если в редакторе ACF макет Flexible Content отображается пустым, повторно импортируйте `acf-landing-import.json` через **ACF → Инструменты → Импорт**. В исправленном файле `layouts` имеет формат объекта с ключами макетов, как в экспорте ACF этого проекта; существующая группа с тем же ключом обновится. После импорта откройте группу «Лендинг: блоки главной» и проверьте вложенные поля макета.

## ACF

Импортируйте [acf-landing-import.json](acf-landing-import.json) через **ACF → Инструменты → Импорт групп полей**. Файл добавляет гибкое содержимое «Блоки страницы» для статической главной страницы и поля цены для записей `services`.

В **Настройки → Чтение** назначьте статическую главную страницу. На её экране редактирования добавьте блоки в нужном порядке: первый экран, преимущества, шаги, услуги, ряды с фото, отзывы, карта, фото выездов, FAQ, форма помощи. Импорт группы полей создаёт структуру редактора, но не заполняет страницу контентом. Для повторяющихся текстовых блоков шаблон содержит стартовый текст; изображения и CF7-шорткоды укажите в админке. Для первого экрана поле «Фоновое изображение для мобильных устройств» необязательно: при его заполнении до 850 px выводится отдельное фото через `picture`, а без него используется основное изображение. После обновления кода повторно импортируйте `acf-landing-import.json`, чтобы поле появилось в редакторе.

Для расчёта времени прибытия импортируйте обновлённый [acf-calculator-settings-import.json](acf-calculator-settings-import.json) и заполните в настройках калькулятора поле «Ключ OpenRouteService для расчёта времени». Вместо поля ключ можно задать константой `SHINA_OPENROUTESERVICE_API_KEY` в `wp-config.php` или переменной окружения сервера `OPENROUTESERVICE_API_KEY`. Калькулятор на отдельной странице и форма карты главной используют один ключ, координаты мастеров и алгоритм расчёта. Координаты мастеров задаются в карте настроек калькулятора; импорт ACF больше не создаёт демонстрационные метки. Если сохранилась старая демонстрационная карта из 30 точек, тема попробует восстановить прежние настроенные координаты, а при их отсутствии оставит карту без меток мастеров. Без ключа показывается настроенное запасное время с пометкой о недоступности маршрута.

Существующие [acf-reviews-import.json](acf-reviews-import.json) и [acf-media-library-photos-import.json](acf-media-library-photos-import.json) используются без изменений. У услуги заполните «Текст карточки на главной» и «Цена от, ₽». Если текст карточки пуст, используется краткое описание записи; без цены карточка остаётся без выдуманного значения. После обновления кода повторно импортируйте `acf-landing-import.json`, чтобы новое поле появилось в редакторе. Ссылки на все услуги и отзывы берутся из архивов соответствующих типов записей. Для фото выездов создайте страницу со slug `vyezdy`, если нужна ссылка «Посмотреть больше выездов».

## Contact Form 7

Создайте четыре формы, вставьте в них разметку файлов ниже и укажите шорткоды созданных форм в полях главной страницы:

| Форма | Разметка CF7 | Поле ACF |
| --- | --- | --- |
| Быстрый вызов | [cf7-quick-call.txt](cf7-quick-call.txt) | Шорткод CF7 быстрого вызова |
| Проверка адреса | [cf7-map-panel.txt](cf7-map-panel.txt) | В блоке карты |
| Помощь | [cf7-help-form.txt](cf7-help-form.txt) | В блоке формы помощи |
| Подтверждение калькулятора | [cf7-calculator.txt](cf7-calculator.txt) | На странице с шаблоном калькулятора |

Проверьте вкладку «Письмо» каждой формы: используйте её реальные mail-теги, например `[phone]`, `[address]`, `[details]`, а для карты также `[callout_price]` и `[arrival_time]`. Отправку и результат обрабатывает CF7; JS только проверяет адрес и заполняет расчётные поля.

## Шаблон и ресурсы

`front-page.php` обходит ACF Flexible Content и подключает соответствующие `template-parts/landing-*.php`. Логика общих элементов находится в `inc/landing.php`. `header.php` выводит общий шаблон `template-parts/site-header.php` на всех страницах: на главной открывает контейнер лендинга после общей липкой шапки, на внутренних страницах выводит ту же шапку перед контентом. `footer.php` выводит общий шаблон `template-parts/site-footer.php` на всех страницах.

Собранные `js/site.css`, `js/site.js` и фоны в `img/` уже размещены в теме. Раскрытие длинных отзывов входит в собранный `js/site.js`: короткие отзывы остаются без кнопки, длинные открываются целиком в диалоге. При изменении исходников выполните `npm run build`, затем скопируйте новые `dist/css/main.*.css` в `js/site.css`, `dist/js/main.*.js` в `js/site.js` и нужные изображения из `dist/img/` в `img/` темы. `generate-landing-acf.cjs` обновляет JSON импорта, а Калькулятор выводится самостоятельным PHP-компонентом `template-parts/landing-calculator.php` с прежними настройками `shina_*` и шорткодом CF7; не генерировать его из Pug.

## Меню шапки

В **Внешний вид → Меню** создайте меню и назначьте его области **Шапка лендинга**. Если она не назначена, шапка использует существующую область **Primary**. Walker выводит до трёх уровней: разделы, подразделы и конечные ссылки. Текущий пункт страницы выводится как `span` с `aria-current="page"`; если у него есть подменю, он остаётся доступным для раскрытия с клавиатуры. Родительские ссылки на мобильном раскрывают вложенные пункты, а отдельная строка «Все услуги» или «Все о …» ведёт на адрес родителя. Для открытия калькулятора из меню используйте произвольную ссылку `#calculator`: на всех страницах она ведёт на страницу с шаблоном калькулятора. На десктопе сохраняются логотип, обычное меню, телефон и CTA; добавлена кнопка «14 экипажей на линии». На мобильном — логотип, экипажи и бургер; телефон выводится в фиксированной панели.

## Меню футера

В **Внешний вид → Меню** создайте отдельное меню и назначьте его области **Футер сайта**. Пункты первого уровня — группы «Услуги», «Клиентам» и «Документы»; ссылки добавьте дочерними пунктами соответствующей группы. Walker выводит группы как раскрывающиеся панели на мобильном и обычные колонки на десктопе. Для двух колонок услуг назовите группу «Услуги» либо задайте ей CSS-класс `footer-services`. Точная текущая страница в меню выводится как `span` с `aria-current="page"`. Телефон футера берётся из `shina_phone`; при наличии `shina_email` выводится и контактный e-mail.

Шапка закреплена сверху при прокрутке на всех страницах; на отдельной странице калькулятора используется его собственная кнопка возврата. Текстовые поля форм, включая CF7, имеют только нижнюю границу с акцентом при фокусе.

Для всех страниц WordPress подключаются одни и те же `js/site.css` и `js/site.js`; состав страницы определяется PHP-шаблонами и их блоками. Инициализация JS проверяет наличие нужных блоков в DOM.

## Новый первый экран и отдельный калькулятор

Повторно импортируйте `acf-landing-import.json`: hero получил короткий оффер и рейтинг. Под кнопкой сохранены тарифы в пределах МКАД и за МКАД, убран только минимальный заказ. Количество отзывов определяется автоматически по опубликованным записям `reviews`; в прототипе — по массиву отзывов. На десктопе содержимое центрируется по высоте экрана с учётом шапки; на мобильном также учитывается нижняя фиксированная панель.

Создайте страницу (например, `/calculator/`) и назначьте ей шаблон **Калькулятор вызова мастера**. URL всех CTA определяется по опубликованной странице с этим шаблоном. На странице заполните шорткод CF7 подтверждения калькулятора; если он не задан, используется прежний шорткод главной. Калькулятор не выводится на главной. `site.css` и `site.js` остаются общими; `js/calculator.js` подключается только на странице калькулятора.

После сборки скопируйте `dist/css/main.*.css` в `js/site.css`, `dist/js/main.*.js` в `js/site.js`, `dist/js/calculator.*.js` в `js/calculator.js`. PHP-разметку калькулятора поддерживать отдельно, сохраняя динамические поля и обёртку CF7. В прототипе переход ведёт на `calculator.html`; возврат работает по истории браузера, при прямом входе ведёт на `index.html`.

## Меню услуг

В меню шапки задайте три уровня: «Услуги» → «Шиномонтаж» / «Техпомощь» → записи услуг. Категории выводятся заголовками колонок; порядок категорий и услуг полностью сохраняется из админки. Используйте пункты меню типа «Услуги» со ссылкой на запись, чтобы Walker получил её ID. Назначенный услуге термин `popular` таксономии `area` добавляет огонёк, не меняя порядок. Иконки пока представлены контурными SVG-заглушками.

## Фильтры услуг

Блок загружает все опубликованные услуги. Фильтр «Все услуги» активен по умолчанию; «Популярные» использует термин `popular` таксономии `area`. Остальные фильтры формируются из назначенных услугам терминов `area`; их названия выводятся из админки. Переключение происходит в браузере без новых запросов. Прежний лимит количества и выбор отдельных услуг в ACF для этого блока больше не ограничивают вывод.

## Иконки и обновлённый блок отзывов

Повторно импортируйте `acf-landing-import.json`. В записи услуги заполните поле **SVG-код иконки услуги** (`service_icon`), используя `currentColor` для цвета. Эта иконка выводится в меню, каталоге и связанных отзывах. Без заполненного поля остаётся контурная заглушка.

В отзыве выберите **Услуга** (`review_service`); поле **Короткий заголовок отзыва** необязательное. Прежний `shina_review_repair_type` используется как резервная связь для старых записей. Фото берутся из существующей галереи `shina_review_gallery`. Фильтры отзывов строятся по связанным услугам; рейтинг и количество берутся из всех опубликованных активных отзывов.

Связь с услугой добавлена непосредственно к существующим записям `reviews`: группа полей подключается темой автоматически через `acf/init`. В редакторе каждого прежнего отзыва выберите «Услуга». Импорт ACF для появления этой связи не требуется; тексты, авторы, даты и фотографии берутся из прежних записей. REST-ответ отзывов также содержит `service_id`, `service_name` и `service_icon`.
