# Статьи в WordPress

## Файлы

- `category-articles.php` — список обычной рубрики со слагом **articles**. Не отдельная страница и не новый CPT.
- `single-article.php` — запись из этой рубрики или её дочерних рубрик. Подключается фильтром из `inc/articles.php`; остальные записи сохраняют прежний выбор шаблона.
- `template-parts/articles-grid.php`, `article-hero.php`, `related-service.php` — компоненты вывода.
- Форма использует существующий `landing-split-form.php`, с поддержкой данных статьи через аргументы. Остальные flexible-блоки продолжают работать прежним способом.
- `acf-articles-import.json` — отдельный импорт для статей; те же группы включены в полный `acf-landing-import.json`. Достаточно импортировать **один** из этих файлов.

## Установка

1. Перенесите новые PHP-файлы и изменённые `functions.php`, `landing-split-form.php`, а также общий `js/site.css`. Остальные общие ресурсы темы должны быть установлены, как для лендинга.
2. В ACF → Инструменты импортируйте `acf-articles-import.json`. Он содержит настройки списка, поля записи и существующую группу гибкого содержимого с добавленной доступностью на рубриках; её ключи сохранены.
3. В Записи → Рубрики создайте или откройте рубрику со слагом **articles**. В меню сайта используйте её настоящий URL. База рубрик и постоянные ссылки могут давать адрес `/category/articles/` — шаблон его не меняет и не создаёт обычную страницу `/articles/`.
4. Добавляйте обычные записи в эту рубрику. Можно создавать дочерние тематические рубрики: их записи тоже попадут в родительский список и получат детальный шаблон.

## Поля списка

На экране редактирования рубрики `articles` доступны H1, вступление заполненного списка, вступление и сообщение пустого состояния, число записей на страницу (по умолчанию 6).

Ниже находится существующее гибкое содержимое `blocks`. Добавьте «Две колонки списков» и «Форма с пояснением», чтобы получить блоки после архива как в прототипе. Сам список и H1 уже выводятся автоматически — не добавляйте ещё один hero. Одинаковые дополнительные блоки выводятся и при пустом списке, поэтому выбирайте для них текст, уместный в обоих состояниях. Тексты примеров находятся в `src/pages/data/articles.js`.

Технически группы доступны на экранах рубрик category, однако параметры этого архива читаются именно у `articles`. Это позволяет не привязывать импорт к ID рубрики конкретной базы.

Пагинация работает через основной запрос WordPress: число страниц реальное, текущий номер — span с aria-current, стрелки SVG. При одной странице пагинации нет. При отсутствии записей нет карточек и пагинации, показываются сообщение и ссылка на архив services. Если у записи нет миниатюры, показывается нейтральная SVG-иллюстрация.

## Поля записи

- Заголовок, основной текст, дата, автор, изображение записи и отрывок — стандартные поля WordPress. Карточка берёт анонс из отрывка, изображение из миниатюры.
- `article_lead` — отдельный лид hero; пустое поле использует отрывок.
- `article_hero_image` — необязательная замена миниатюры для фона hero.
- `article_author_label` — необязательная подпись вместо имени автора WordPress.
- `article_show_contents` — автоматическое оглавление по H2. Существующие уникальные id сохраняются, для остальных создаются якоря; текст не требуется разбивать на ACF-поля. При отключении оглавления или отсутствии H2 боковая колонка не выводится.
- `article_service` — одна запись services. Заголовок, описание и ссылка берутся из выбранной услуги. Черновик, удалённая запись и неверный тип не выводятся.
- `article_form_title`, `article_form_lead`, `article_form_shortcode` — форма под статьёй. Если личный шорткод пуст, используется `articles_form_shortcode` из рубрики `articles`. Если оба пусты, форма не выводится.

Время чтения рассчитывается по тексту — примерно 180 слов в минуту. Основной контент проходит стандартные фильтры `the_content`, поддерживает обычные HTML-теги и блоки редактора. Для защищённой паролем записи отображается штатная форма пароля, содержимое, оглавление, связанная услуга и контактная форма не раскрываются.

## CF7 и стили

Используйте существующую форму из `cf7-help-form.txt`. Для статьи вставьте её шорткод в поле статьи или резервное поле рубрики. Для списка шорткод указывается в `help_form_shortcode` гибкого блока формы. Отправка и события CF7 остаются в существующем JS; новый submit-обработчик не добавлялся.

Компонентные стили из исходников добавлены в конец **общего** `js/site.css` между маркерами `BEGIN ARTICLE COMPONENTS` / `END ARTICLE COMPONENTS`. Предыдущие байты файла сохранены. Отдельного CSS-файла и подключения нет. При дальнейшем изменении исходных SCSS обновляйте этот фрагмент или используйте принятую сборку общих ресурсов темы.

Заголовок страницы и SEO-метаданные выводятся обычным механизмом WordPress/SEO-плагина через wp_head; демонстрационные метаданные и фото из Pug в PHP не зашиты. База данных, рубрика и записи автоматически не создавались. PHP/Studio CLI здесь недоступны: вывод на работающем WordPress и отправка CF7 требуют проверки после установки.
